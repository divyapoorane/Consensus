2. PHASE 0 — COMPREHENSIVE ARCHITECTURAL AUDIT
--------------------------------------------------------------------------------

1. How winners are currently finalized:
   - In `frontend/src/app/organizer/Results.tsx`, winner selection is rendered via an
     in-memory ranked list (`projects` state).
   - The "Finalize & Lock Winners" button triggers `handleFinalizeWinners()`, which
     sets local component state (`finalized = true`), displays a confirmation alert,
     and routes the user to `/organizer/payouts`.
   - On the backend, `backend/src/routes/hackathons.ts` supports hackathon lifecycle
     states ("active", "completed"), while `backend/src/routes/payouts.ts` tracks
     settlements. Winner certificates are currently issued independently on demand via
     `POST /api/certificates/issue`.

2. Where final results are persisted:
   - `Submission` table (`backend/prisma/schema.prisma`): Holds `status` ("submitted",
     "under_review", "evaluated", "won"), `score` (Float), `maxScore` (Float),
     `judgingStatus`, and `feedback`.
   - `Evaluation` table: Stores per-juror rubric score breakdowns (`innovation`,
     `technicalQuality`, `uiUx`, `impact`, `presentation`, `totalScore`, `feedback`).
   - `Payout` table: Records prize distributions associated with finalized placements.
   - `Certificate` table: Stores issued participant, judge, and winner credentials.

3. Whether certificates already have a database model:
   - YES. `model Certificate` is defined in `backend/prisma/schema.prisma`:
     * id             : String (UUID primary key)
     * certificateId  : String (unique identifier, e.g. "CERT-CNS-2026-904")
     * recipientName  : String
     * recipientEmail : String
     * type           : String ("participant", "winner", "judge")
     * hackathonId    : String (foreign key to Hackathon)
     * hackathonTitle : String
     * achievement    : String
     * issuedAt       : DateTime
     * status         : String ("issued", "draft")
     * createdAt      : DateTime

4. Whether certificates already have any generation/download implementation:
   - YES. A complete, production-quality implementation exists in
     `backend/src/routes/certificates.ts`:
     * `GET /api/certificates`: Retrieves issued certificates with participant isolation.
     * `POST /api/certificates/issue`: Generates new certificate records with audit logs.
     * `GET /api/certificates/:id/download`: Renders and streams a real, vector PDF
       document using `PDFDocument` (`pdfkit`) in landscape A4, containing dark
       theme styling, double borders, official seals, recipient name, track title,
       distinction details, and signatures.

5. Whether realtime/WebSocket infrastructure already exists:
   - NO. Neither `socket.io`, `ws`, nor WebRTC signaling packages are installed in
     `backend/package.json` or `frontend/package.json`. The backend server
     (`backend/src/index.ts`) is a standard Express 4 REST application without an
     attached WebSocket or HTTP upgrade server.

6. Whether the project already has a media/file storage mechanism:
   - The platform generates PDF files on-the-fly and streams them directly over HTTP

   - Image assets and avatar URLs are referenced as string URIs. There is no S3/GCS
